## 真实截图与保存验证

本次从当前工作区构建并实际启动了 LiteMd：

```sh
GOFLAGS=-tags=e2e go tool mygo build -debug -skip-dmg -o /tmp/litemd-wechat-build
```

通过应用自带的 `mygo-automation` 接口打开示例、切换模式，并以 macOS `screencapture` 捕获真实原生窗口，未用网页或设计稿模拟界面。

- 主示例：`demo/打开就看.md`。
- 保真示例：`demo/只改这一段.md`。
- 修改前原始字节：`evidence/fidelity-before.md`。
- 修改后原始字节：`evidence/fidelity-after.md`。
- 实际差异：`evidence/fidelity.diff`。

在所见即所得模式下，把正文中的「错别字」替换成「小问题」，执行实际保存。核对结果：修改后的文件恰好等于原始文件执行这一次文字替换的结果，其余字节全部一致。这是单个演示样例的结果，不等于对所有 Markdown 的全面保证。

应用加载成稿后，检查了正文引用的 5 张图片，均已完成解码。`article.html` 由真实 LiteMd 的 HTML 导出生成，再把内嵌图片还原为本目录相对路径，并补充了预览用排版。所有图片引用均经过文件存在性检查。

截图期间暂时将应用设为中文、浅色，并关闭更新检查。已退出此次启动的应用，还原原有设置、窗口状态和最近文件记录。

模型：`ldigit/codex/gpt-image-2`。

- `illustration-focus.png`：生成任务 `image-30954-1`，参考仓库 `resources/icon.png`。
- `cover-background.png`：生成任务 `image-30954-2`，参考本次真实 `app-preview-wide.png`、仓库图标以及概念插画。生成背景时预留截图位置，最终界面来自原始截图直接叠加。

运行 `swift docs/wechat/compose.swift` 可使用现有素材重新合成封面与 diff 对比图，无需重新调用生图工具。

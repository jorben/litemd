| 项 | 内容 |

## 1. 产品定位

**LiteMd 是一个“打开就看、需要就改”的 Markdown 文件查看与编辑器。**

它像系统的图片查看器：双击一个 `.md` 文件，弹出一个只属于这个文件的窗口，窗口里可以阅读，也可以直接编辑，改完关掉就走。它不管理文件，不建文档库，也不做笔记。

一句话：**一个文件，一个窗口，所见即所得，原文不走样。**

### 1.1 要解决的问题

- 系统自带工具打开 `.md` 只能看到源码（记事本、文本编辑），或者根本打不开。
- 现有 Markdown 编辑器大多以“文件夹 / 工作区 / 笔记库”为中心（Obsidian、VS Code、Typora 的侧栏、vmark 的工作区），只想看一眼、改一处时显得重。
- 富文本式编辑器保存时经常改写原文（列表符号、空行、表格对齐），在 Git 仓库里产生无关 diff。

### 1.2 目标用户与典型场景

| 用户 | 场景 |
|---|---|
| 开发者 | 打开仓库里的 `README.md`、`CHANGELOG.md`、设计文档，阅读或小改，要求保存后 diff 干净 |
| 写作者、产品/运营 | 收到别人发来的 `.md` 文件，双击就能像看文档一样阅读，顺手改错字、加段落 |
| AI 工具用户 | 查看 AI 生成的 Markdown 报告（含表格、公式、Mermaid），需要漂亮的渲染和导出 PDF |

## 2. 设计原则

1. **文件就是唯一的真实数据。** 不建数据库，不另存副本（崩溃恢复副本除外），不往文件里写任何私有标记。
2. **原文不走样。** 只打开不编辑，绝不改动文件；编辑后保存，只有改动的地方变化。
3. **一个文件一个窗口。** 窗口之间相互独立，没有标签页、没有侧栏文件树。
4. **轻和快。** 打开要快，空闲时不占资源，安装包要小。
5. **不打扰。** 默认不联网（检查更新除外，可关闭），无账号，无统计，无弹窗推销。

## 3. 范围总览

### 3.1 v1 做

| 模块 | 内容 |
|---|---|
| 窗口与文件 | 一个文件一个窗口；无文件启动时显示带「新建 / 打开」入口和最近打开列表的启动窗口；双击/拖入/命令行打开；新建、打开、最近打开、保存、另存为、还原；自动保存与崩溃恢复；外部修改检测 |
| 查看与编辑模式 | 预览（只读）、所见即所得、源码、分屏（源码 + 预览）四种，可随时切换 |
| 语法与渲染 | CommonMark + GFM（表格、任务列表、删除线、自动链接）；KaTeX 公式；Mermaid；YAML frontmatter；脚注；GitHub 提示块；`<details>` 折叠块；代码高亮 |
| 编辑辅助 | 快捷键、Markdown 输入规则、选中文字浮动格式栏、表格编辑、链接与图片编辑 |
| 图片 | 显示本地相对路径和网络图片；粘贴、拖入图片自动存到本地目录并插入相对路径 |
| 导航 | 大纲面板；文档内查找替换 |
| 导出 | 导出 HTML、导出 PDF、打印 |
| 外观 | 浅色/深色（跟随系统）；字号缩放；正文宽度 |
| 其他 | 自动更新；设置窗口；简体中文与英文界面 |
| 平台 | macOS（Apple Silicon + Intel）、Windows 10/11 x64 为正式支持；Linux 尽力支持 |

### 3.2 v1 不做（明确边界）

| 不做 | 原因 / 替代 |
|---|---|
| 文件树、侧栏、文件夹/工作区 | 违背“一个文件一个窗口”的定位。用系统的访达/资源管理器 |
| 标签页、窗口合并 | 同上。多个文件就是多个窗口 |
| 笔记库、标签、收藏、跨文件搜索 | 不做笔记产品 |
| 双链、`[[wiki link]]`、反向链接 | 属于笔记库功能。`[[...]]` 按普通文本原样保留 |
| 账号、云同步、协作 | 本地工具。同步交给 iCloud/网盘/Git |
| AI 功能、MCP 集成 | v1 不做，见第 9 节 |
| 插件系统、自定义 CSS 主题 | v1 只提供内置的浅色/深色。自定义 CSS 列入以后 |
| 导出 Word（docx）、Pandoc 集成 | 依赖外部工具，体积和维护成本高 |
| JSON/YAML/HTML 等其他格式 | 只做 Markdown（`.md` `.markdown` `.mdown` `.mkd`）。`.txt` 可以通过打开对话框、命令行、拖入启动窗口手动打开，但**不注册文件关联**，不抢系统默认程序 |
| Vim/Emacs 键位、演示模式、打字机模式、专注模式 | 非核心，列入以后 |
| 非 UTF-8 编码的编辑（GBK、Big5 等）、编码自动识别与手动选择 | v1 只读打开并提示，可另存为 UTF-8，见 F2.6 |
| Mac App Store、移动端 | 分发走官网/GitHub Releases（签名 + 公证） |

## 4. 功能需求

优先级：**P0** 必须有，没有就不能发布；**P1** v1.0 要有；**P2** 有余力再做，可推迟到 v1.x。

### F1 窗口与打开方式

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1.1 | 在访达/资源管理器双击 `.md` 文件，用 LiteMd 打开（安装时注册文件关联，用户可设为默认程序） | P0 |
| F1.2 | **每个文件一个独立窗口**；同一个文件再次打开时，聚焦已有窗口，不开第二个 | P0 |
| F1.3 | 应用已在运行时，再打开文件不启动第二个进程，而是在现有进程里新开窗口（单实例） | P0 |
| F1.4 | 拖文件到 Dock 图标/任务栏图标/已打开的窗口标题栏上打开；拖到正文区域视为插入（见 F6） | P1 |
| F1.5 | 命令行 `litemd <文件...>` 打开；文件不存在时先创建空文件再打开（用户显式指定路径，视为同意创建）。macOS 通过设置中的「安装命令行工具」提供 `litemd` 命令 | P1 |
| F1.6 | 菜单：新建（未命名文档）、打开…、打开最近（最多 10 个，可清空；与系统 Dock 菜单/跳转列表一致，D8）、关闭窗口 | P0 |
| F1.7 | 窗口标题显示文件名；有未保存改动时，macOS 关闭按钮带圆点，Windows/Linux 标题前加 `*` | P0 |
| F1.8 | 没有记录过位置的新窗口，相对当前窗口向右下错开层叠排开；按文件记住上次的窗口大小、位置和查看模式 | P1 |
| F1.9 | 不带文件启动时（从启动台、开始菜单、Dock 直接启动），所有平台都显示**启动窗口**（F1.12）；不自动新建未命名文档，也不弹打开对话框。带文件启动或有待恢复的文档时不显示启动窗口 | P0 |
| F1.10 | 关闭最后一个文档窗口：macOS 应用保留在 Dock，不自动弹窗；之后点 Dock 图标（无可见窗口时）显示启动窗口。Windows/Linux 退出进程 | P1 |
| F1.12 | **启动窗口**：一个小的应用框架窗口，只提供两个入口——「新建」（⌘N）和「打开…」（⌘O），并支持把 `.md` 文件拖到窗口上打开。规则：<br>① 全局只有一个启动窗口，重复触发时聚焦已有的；<br>② 任何文档窗口打开后（不论从启动窗口、菜单还是访达），启动窗口自动关闭；<br>③ 在打开对话框中取消，启动窗口保留；<br>④ 关闭启动窗口：macOS 应用留在 Dock；Windows/Linux 在没有其他窗口时退出；<br>⑤ 按钮下方按最近访问时间倒序列出最近打开的文件（最多 5 个，与文件菜单「打开最近」同源，已不存在的文件不列出），点击即打开；提供「清除记录」入口，效果同「打开最近 › 清除菜单」。不显示其他文件列表，仍保持“不做文件管理”的边界（D16） | P0 |
| F1.11 | macOS 标题栏代理图标：可拖出文件、⌘ 点击查看路径（mygo `NewDocuments` 提供） | P2 |

### F2 保存与文件安全

| 编号 | 需求 | 优先级 |
|---|---|---|
| F2.1 | 保存（⌘S）、另存为、还原到磁盘版本；macOS 另有副本、重命名、移动到（mygo 提供）。快捷键跟随平台惯例（D9）：macOS 另存为 ⌥⇧⌘S、副本 ⇧⌘S；Windows/Linux 另存为 Ctrl+Shift+S | P0 |
| F2.2 | **自动保存（默认开启）**：已存在于磁盘的文件，停止输入约 1 秒后自动写盘，窗口失焦和关闭时也写；未命名文档不自动保存，关闭时询问。设置中可关闭自动保存（关闭后改为关窗时询问）；**开关在重启应用后生效**（D11） | P0 |
| F2.3 | **崩溃恢复**：未保存的改动持续写入恢复副本；崩溃或强制退出后再次启动，自动以“未保存”状态重新打开这些文档，窗口顶部显示提示条「已恢复上次未保存的内容」，提供「保留」「丢弃，载入磁盘版本」两个选项；恢复过程不覆盖磁盘原文件（D10） | P0 |
| F2.4 | **外部修改检测**：文件被其他程序改动时，本地没有未保存改动（包括页面里尚未同步的输入）则静默重新载入（保留滚动位置）；有冲突则在窗口顶部显示提示条：「载入磁盘版本 / 保留我的版本 / 对比」（对比为 P2）。冲突未处理时用户主动保存或关窗，由系统对话框询问（D12）。文件被删除或移走时提示，允许另存 | P0 |
| F2.5 | **原文保真**：<br>① 只打开不编辑，任何情况下不写盘；<br>② 源码模式下编辑，保存结果与编辑内容逐字节一致；<br>③ 所见即所得模式下编辑，未改动的块保持原文（空行、列表符号、强调符号、表格对齐、代码块围栏、链接写法），只有改动的块按规范格式写出；<br>④ 保留原文件的换行符（LF/CRLF）、末尾换行、UTF-8 BOM。已知例外：同一文件混用 LF 和 CRLF 时，编辑后统一为占多数的一种；<br>⑤ 所见即所得中的一次编辑如果无法只改动局部（极少数情况），仍然写入（数据安全优先），并在提示条中说明“本次修改调整了全文格式”，可撤销 | P0 |
| F2.6 | 编码：UTF-8（含 BOM）正常读写。带 BOM 的 UTF-16 按 UTF-16 显示；其他不是合法 UTF-8 的文件一律按 GB18030 解码显示（可能出现乱码）。这两类都以只读方式打开，顶部提示“此文件不是 UTF-8 编码，暂不支持编辑”，提供「另存为 UTF-8」，另存后的新文件可正常编辑；原文件不改动（D14） | P1 |
| F2.7 | 写盘采用“写临时文件 + 原子替换”，保留原文件的权限；写盘失败（只读、磁盘满、权限不足）时提示并保持未保存状态，可另存 | P0 |
| F2.8 | 只读文件（权限只读、锁定）以只读模式打开，窗口显示“只读”标记 | P1 |

### F4 Markdown 语法与渲染

| 编号 | 语法 | 预览 / 所见即所得 | 优先级 |
|---|---|---|---|
| F4.1 | CommonMark 全部语法（标题含 ATX 和 setext 两种写法、段落、强调、列表、引用、代码、链接、图片、分隔线、HTML 实体） | 渲染并可编辑 | P0 |
| F4.2 | GFM：表格（含列对齐）、任务列表、删除线（`~~x~~` 与 GitHub 一样也认 `~x~`）、自动链接 | 渲染并可编辑；所见即所得中任务框可直接勾选 | P0 |
| F4.3 | 代码块语法高亮（常用约 30 种语言），显示语言标签，可一键复制 | 渲染并可编辑 | P0 |
| F4.4 | 公式：行内 `$...$`、块级 `$$...$$`（KaTeX） | 渲染；点击进入源码编辑并实时预览 | P0 |
| F4.5 | Mermaid 代码块 | 渲染为图；点击编辑源码；渲染失败显示错误和源码 | P1 |
| F4.6 | YAML frontmatter | 原样保留；预览中折叠显示为一个元数据区，可展开编辑 | P0 |
| F4.7 | 脚注 `[^1]` | 渲染上标和文末脚注列表，悬停显示内容 | P1 |
| F4.8 | GitHub 提示块 `> [!NOTE]` `[!TIP]` `[!IMPORTANT]` `[!WARNING]` `[!CAUTION]` | 渲染带图标的样式块 | P1 |
| F4.9 | `<details><summary>` 折叠块 | 渲染为可折叠块 | P1 |
| F4.10 | 原始 HTML（行内与块级） | 经过安全过滤后渲染（见 NF5）；所见即所得中作为不可直接编辑的块，点击编辑源码 | P1 |
| F4.11 | 无法识别的语法（如 `[[wiki]]`、`==高亮==`、`^上标^`、`++下划线++`、自定义容器） | 按普通文本显示并原样保留，不报错、不丢失（D13：v1 不启用 vmark 的这些扩展语法） | P0 |

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NF1 | 启动与打开速度 | 冷启动到显示内容 < 1 s；应用已运行时打开新文件到显示内容 < 400 ms（基准：Apple M1 / 16GB、100 KB 文档、预览模式） |
| NF2 | 编辑流畅度 | 1 MB（约 50 万字）文档在所见即所得和源码模式下连续输入无可感知卡顿（输入到上屏 P95 < 16 ms）。超过 5 MB 的文件默认以源码模式打开并提示；超过 20 MB 只读打开 |
| NF3 | 资源占用 | 单个窗口空闲内存 < 150 MB（含 WebView 进程）；空闲时 CPU ≈ 0；同时打开 20 个窗口可用 |
| NF4 | 安装包大小 | macOS DMG < 25 MB；Windows 安装包 < 20 MB（WebView2 使用系统自带，不打包） |
| NF5 | 安全 | 文档中的 `<script>`、事件属性（`onclick` 等）、`javascript:` 链接一律不执行；HTML 经过白名单过滤；启用严格的内容安全策略（CSP），即使过滤遗漏，注入的脚本也不能执行；后端接口只按当前窗口的文档限定作用域，不提供按任意路径读写的接口；本地资源只提供图片类文件（允许 `../` 等文档目录之外的路径，否则大量文档无法显示图片）；写盘只发生在文档本身、其 assets 目录和用户在对话框中选择的路径；导出和打印用的页面不能调用任何后端接口；点击文档中指向本地可执行文件的链接一律不打开 |
| NF6 | 隐私 | 无账号、无遥测、无崩溃自动上报；唯一的默认网络请求是检查更新（可关闭）和文档中的网络图片（可关闭） |
| NF7 | 可靠性 | 任何情况下不丢用户内容：写盘原子化、恢复副本、写盘失败保持未保存；保真度回归测试（见第 7 节）每次构建都跑 |
| NF8 | 兼容性 | macOS 13+；Windows 10 21H2+ / Windows 11（WebView2 Runtime）；Linux：WebKitGTK 4.1，Ubuntu 22.04+ |
| NF9 | 输入法 | 中文、日文输入法在所有编辑模式下可正常组字、候选框位置正确、组字过程中不触发快捷键和输入规则 |
| NF10 | 无障碍 | 菜单和对话框支持键盘操作；预览内容可被系统读屏读取（WebView 原生能力） |

## 7. 验收标准（v1.0 发布条件）

1. 所有 P0 需求完成，P1 需求完成 ≥ 90%，未完成项有明确去向。
2. **保真度回归集**通过：收集 ≥ 200 个真实 `.md` 文件（主流开源项目的 README/文档、含中文的文档、AI 生成的报告、边界语法样例）：
   - 打开 → 保存（无编辑）：**100% 零字节差异**；
   - 所见即所得中做一次随机小改 → 保存：diff 只出现在改动的块，**≥ 98%** 文件满足；不满足的逐个列出原因；
   - 源码模式编辑 → 保存：100% 与编辑内容一致；

4. macOS、Windows 上完成冒烟清单：双击打开、单实例、多窗口、自动保存、崩溃恢复、外部修改、图片粘贴、导出 PDF、自动更新。
5. 中文输入法（macOS 自带拼音、Windows 微软拼音、搜狗）在四种模式下手工验证通过。
6. **D3**：所见即所得模式下未改动块保持原文（第 2 条的 ≥ 98% 指标）为发布阻断条件。

## 附录 A：与 vmark 的关系

- vmark（xiaolai/vmark，ISC 许可）提供：remark ↔ ProseMirror 的 Markdown 管线（`src/utils/markdownPipeline`，约 1.1 万行，基本不依赖应用状态）、Tiptap 所见即所得编辑组件、CodeMirror 6 源码编辑组件、若干编辑插件，以及对 micromark / mdast / prosemirror-view 的补丁。
- LiteMd 不 fork vmark 整个应用，只挑选上述模块迁入，后端由 Tauri（Rust）换成 mygo（Go）。
- ISC 与本仓库的 Apache-2.0 兼容；迁入的代码保留原版权声明，并在 `THIRD_PARTY.md` 中列出来源和许可。
- vmark 迭代很快且不接受 PR，迁入后按需单向挑选上游改动，不追求同步。
